Scope checklist

Before any security test

  • Exact hostname or asset is listed as in-scope
  • Excluded domains and paths are understood
  • Allowed testing methods are checked
  • Rate limits and testing windows are known
  • Safe-harbor and disclosure rules are read
  • Written permission can be produced if requested

Report quality checklist

Help a security team reproduce and understand a valid issue.

  • Clear title and affected in-scope asset
  • Impact explained without exaggeration
  • Minimal, repeatable steps
  • Expected and actual results
  • Redacted screenshots or request/response evidence
  • No exposed credentials, tokens or personal data
